# Theming

Rakitmimpi UI ships two themes. Every color is a Tailwind v4 theme variable defined in
`src/styles.css`; dark mode redefines the same variables, so components carry no
`dark:` classes — utilities like `bg-surface` and `text-secondary` just
resolve differently.

<ThemeDemo />

Two ways to drive this:

- the **Theme** control in the toolbar above — switches any story canvas

## Turning dark mode on

Dark applies when either is true:

- `<html data-theme="dark">` — an explicit choice
- the OS prefers dark **and** no `data-theme="light"` is set

`data-theme` is the only contract. Set it however you like, or use the hook.

```tsx
import { useTheme } from "@rakitmimpi-ui/ui";

function ThemeToggle() {
  const { resolvedTheme, toggleTheme } = useTheme();

  return (
    <Button variant="outline" onClick={toggleTheme}>
      {resolvedTheme === "dark" ? "Light mode" : "Dark mode"}
    </Button>
  );
}
```

`useTheme()` needs no provider — it reads a module-level store, so every caller
stays in sync. It returns:

| Field             | Type                            | Notes                                             |
| ----------------- | ------------------------------- | ------------------------------------------------- |
| `theme`           | `"light" \| "dark" \| "system"` | what the user picked                              |
| `resolvedTheme`   | `"light" \| "dark"`             | what is on screen                                 |
| `setTheme(theme)` |                                 | persists to `localStorage` under `rakitmimpi-ui-theme` |
| `toggleTheme()`   |                                 | flips light ↔ dark as an explicit choice          |

The default is `"system"`, which follows `prefers-color-scheme` and keeps
following it until the user chooses. `setTheme("system")` clears the stored
choice and hands control back to the OS.

### Avoiding a flash of the wrong theme

React applies the theme after hydration, which is one paint too late. Drop the
exported `themeScript` into `<head>` as a blocking script:

```tsx
import { themeScript } from "@rakitmimpi-ui/ui";

// biome-ignore lint/security/noDangerouslySetInnerHtml: must run before paint
<script dangerouslySetInnerHTML={{ __html: themeScript }} />;
```

Lower-level pieces are exported too, for apps that manage theme themselves:
`applyTheme`, `initTheme`, `resolveTheme`, `getSystemTheme`, `getStoredTheme`,
`setStoredTheme`, `getAppliedTheme`, `subscribeToSystemTheme`,
`THEME_STORAGE_KEY`, `THEME_ATTRIBUTE`.

Neither theme uses pure black or pure white for text — near-black and soft-white
read as less harsh.

These two are named `primary`/`secondary` rather than `text-primary`/`text-secondary`
so the utilities read `text-primary` and `text-secondary`. Worth knowing: that
makes `bg-primary` a near-black fill, **not** the brand navy — the brand is
`bg-accent`.

Status colors are the only greens, ambers, and reds in the system. Reach for
`bg-success` / `bg-warning` / `bg-error` — never a Tailwind palette color like
`bg-green-600`, which will not flip with the theme.

## Contrast

`--color-overlay` is the one token with no contrast requirement: it is a scrim,
never a text or border colour, and `Dialog` paints it at 60% opacity. It stays
on the dark end of the ramp in both themes — a light scrim over a dark page
reads as a flash rather than a dimming, which is why it does not mirror the
usual light/dark flip.

Measured WCAG 2.1 ratios for the pairings components actually use. Body text
needs 4.5:1; non-text UI boundaries need 3:1.

| Pairing                           | Light   | Dark    |
| --------------------------------- | ------- | ------- |
| `primary` on `surface`            | 16.88:1 | 14.76:1 |
| `secondary` on `surface`          | 6.13:1  | 6.63:1  |
| `secondary` on `surface-alt`      | 5.41:1  | 6.19:1  |
| `accent-foreground` on `accent`   | 10.06:1 | 10.06:1 |
| `success-foreground` on `success` | 4.66:1  | 4.70:1  |
| `warning-foreground` on `warning` | 5.12:1  | 7.90:1  |
| `error-foreground` on `error`     | 5.34:1  | 4.61:1  |
| `input` border on `surface`       | 3.52:1  | 3.30:1  |
| `ring` on `bg`                    | 10.06:1 | 4.74:1  |

Two notes on why extra tokens exist:

- **`--color-input` is darker than `--color-border`.** The spec border
  (`#E3E5E8` / `#242C3B`) sits at ~1.2:1 against a surface. That is fine for a
  decorative divider but fails WCAG 1.4.11 as the visual boundary of a text
  field, so form controls get their own stronger value.
- **`--color-ring` is not the accent in dark.** `#2E3A6E` is 1.75:1 against the
  dark page — an invisible focus indicator. The dark ring keeps the hue and
  lifts the lightness until it clears 3:1 everywhere.

Note that `accent` used as _text_ on a dark surface is 1.60:1 and must not be
used that way — on dark, link and active-nav text should use `text-ring` or
`text-accent-secondary`.

## Tables

Zebra-stripe with `surface-alt`, which is one step off the page in both themes:

```tsx
<table className="w-full border-collapse text-sm">
  <thead>
    <tr className="border-border border-b text-left text-secondary">
      <th className="px-3 py-2 font-medium">Invoice</th>
      <th className="px-3 py-2 font-medium">Status</th>
    </tr>
  </thead>
  <tbody>
    {rows.map((row) => (
      <tr key={row.id} className="odd:bg-surface even:bg-surface-alt">
        <td className="px-3 py-2">{row.id}</td>
        <td className="px-3 py-2">
          <Badge variant={row.status}>{row.status}</Badge>
        </td>
      </tr>
    ))}
  </tbody>
</table>
```

## Overriding tokens

Tokens are plain Tailwind theme variables, so redefine them after importing the
stylesheet. Override both themes or you will only fix one:

```css
@import "tailwindcss";
@import "@rakitmimpi-ui/ui/styles.css";
@source "../node_modules/@rakitmimpi-ui/ui/dist";

@theme {
  --color-accent: #1f6f4a; /* light */
}

:root[data-theme="dark"] {
  --color-accent: #2e8b5f;
}
```
